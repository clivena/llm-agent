# 运行环境与部署

## 依赖组件

本地开发依赖三个组件：缓存、关系库、消息队列。前两个用于配额与账本，
消息队列用于账本流式落库，默认配置下可以不启用。

关系库的宿主端口特意改成了五位数端口。原因是本机可能存在另一个原生安装的实例
占用默认端口，连接会落到那个没有目标库的实例上并报连接被重置。
这类问题排查时容易误判成密码错误或网络问题。

## 连接必须是惰性的

关系库连接采用惰性初始化。缓存或关系库没有启动时应用仍然能启动，
只在真正使用到的时候失败并记录日志，不影响主链路的其他部分。

这条性质对本地开发很重要：先起网关、后起依赖的顺序是常见操作，
如果应用启动时强校验依赖，开发体验会变得很糟。

## 进程端口被环境变量劫持

应用服务器的端口曾经被一个环境变量意外覆盖，导致服务监听的端口与配置不一致，
表现为“配置里写着 8080，实际连不上”。

排查这类问题的顺序是：先确认进程实际监听的端口，再回头查环境变量，
而不是先去改配置文件。配置只描述期望值，环境变量和命令行参数优先级更高。

## 本地代理与回环地址

本机经常设有全局 HTTP 代理。客户端库默认会把代理套用到所有请求上，
包括指向回环地址的请求，于是“连本地服务”会变成“经代理再打回本机”，
表现为连接被拒或者隧道建立失败。

排查时容易把方向误判到服务端配置上。正确的处理是在客户端显式声明
对回环地址不使用代理，而不是去修改服务端。

## 独立部署与隔离

构建产物需要与用户本机的环境隔离：依赖下载到项目独立的仓库目录，
虚拟环境建在项目外部，避免污染全局环境。这样任何一步失败都不会影响其他项目，
也让“换一台机器能不能跑起来”这个问题有一个确定的答案。
