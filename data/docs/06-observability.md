# 可观测性

## 全链路追踪标识

每个进入网关的请求都会带一个追踪标识。如果请求头里已经带了，就沿用它；
没有则生成一个新的。无论哪种情况，都会写入响应头回写出去。

回写这一步经常被忽略，但它是追踪能不能用的关键。调用方拿不到标识，
就没有办法用它去账本里查出这次请求对应的记录，所谓全链路就断了。

追踪标识在整条链路上必须显式传递。在响应式框架里没有线程本地存储可用，
因为一次请求可能跨越多个线程。正确做法是放在请求上下文属性里，
在需要的地方显式取出并向下传，而不是依赖隐式的上下文。

## 关键指标

埋点的选择围绕一个问题：出错时先看哪个数字。

缓存命中与未命中用于判断成本是否符合预期，命中率突然掉下来通常意味着
提示词被改动或者缓存键变了，而不是业务量变化。

级联升级计数用于判断弱模型是否在退化。这个数字持续上升说明质量阈值
或者事实性发生了变化，应该去看具体样本而不是只调阈值。

账本落库成功与失败两个计数是一对。失败计数一旦上涨，说明对账会缺数据，
这属于必须立刻处理的问题，因为它不会表现为用户可见的错误。

## 反例：把错误都写成成功

早期实现把所有错误都写成 HTTP 200，错误信息放在响应体里。
这导致两个后果：客户端无法用状态码判断该退避还是该重试，
监控也无法通过错误率发现上游大面积故障。

现在按语义区分状态码：额度耗尽返回表示限流的码，上游或适配异常返回表示网关下游出错的码，
参数错误返回表示请求非法的码。客户端可以据此决定重试策略。

## 只读运维接口

面板读的数据来自一组只读接口，它们不扣配额、不写账本、不改配置，
因此不会影响主链路的任何语义。主链路与运维接口完全隔离，
运维接口挂了不影响对外服务。

依赖健康检查把探测异常一律降级为不可用，而不是让它自己报错。
面板的意义是告诉人哪里坏了，而不是跟着一起坏。
